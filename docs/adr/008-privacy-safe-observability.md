# ADR-008：分离源消息与规则执行指标并最小化日志内容

- 状态：Proposed
- 日期：2026-09-26
- 相关提交：[`616b9e2`](https://github.com/svlic/TFor/commit/616b9e2dcbd634a50640d576440d63ec80fffb56)、[`cd59c27`](https://github.com/svlic/TFor/commit/cd59c270eb34c6b801aa1f126978646dc5912d61)

## 背景

一条源消息可以命中多条规则，因此“收到消息数”和“规则执行数”不能混为同一指标。日志需要支持短期排障，同时控制 SQLite 存储成本。

## 决策

分别记录源消息事件和规则执行日志。Dashboard 展示最近 24 小时的 received 与 executions，并区分过滤、Forward、Copy 和失败。

处理日志保留 3 天。日志不保存正文、caption、过滤值或命中片段；可以保存 sender name、username、sender ID 及其他处理元数据。当前不需要日志导出、外部日志系统或复杂聚合。

`deleted` 等内部结果不需要加入 Dashboard 指标和日志筛选项。

## 可确认的实现事实

- `source_events` 和 `processing_logs` 分表存储。
- 日志保存账号、源消息 ID、发送者元数据、规则、目标、过滤步骤结果、实际模式、错误和耗时。
- 3 天保留时间是代码常量；启动时和之后每小时清理。
- 默认查询 200 条，最大 1000 条。

## 后果

- 多规则命中不会虚增 received。
- 不保存消息内容降低了隐私风险和数据库增长速度，但限制事后内容级排障。
- sender 元数据被明确视为允许记录的信息。
- 固定 3 天是基于存储成本的选择，而不是合规保留期。

## 未决问题

- 暂无。若未来引入外部指标或日志服务，应另作决策。
