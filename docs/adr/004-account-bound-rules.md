# ADR-004：规则绑定单一账号并允许重复配置

- 状态：Proposed
- 日期：2026-09-26
- 相关提交：[`616b9e2`](https://github.com/svlic/TFor/commit/616b9e2dcbd634a50640d576440d63ec80fffb56)、[`cd59c27`](https://github.com/svlic/TFor/commit/cd59c270eb34c6b801aa1f126978646dc5912d61)

## 背景

每条规则描述一个 Telegram Source 到一个 Target 的转发动作。跨账号收发没有必要；如需跨账号流转，应通过 Telegram Channel 等外部中转完成。

## 决策

每条规则在任一时刻只绑定一个账号，该账号同时负责监听 Source 和发送到 Target。规则可以整体改绑到另一个账号，但禁止 Source 与 Target 分属不同账号。

允许创建 Source、Target 和其他参数相同的重复规则。重复配置造成的多次发送由用户自行管理，系统不做目标去重或唯一性约束。

规则保存时由绑定账号解析 Source/Target Chat ID，只支持频道和群组。保存后的修改应实时生效，无需重启 Client。

## 可确认的实现事实

- `rules.account_id` 是必填外键。
- Source/Target 的 ID、名称和类型快照保存在规则中。
- 保存时通过在线 Telegram Client 解析 Chat ID，并拒绝私聊。
- 每次处理任务都会重新读取规则。
- 账号归档会停用关联规则，但不删除它们。

## 后果

- 权限边界和运行时状态较简单。
- 重复规则会产生重复发送，这属于允许的用户配置结果。
- 名称快照可能过期；名称不要求同步刷新，未来可以异步更新。
- 未来可能需要规则组来简化批量管理，但不改变禁止跨账号的约束。

## 未决问题

- 规则组需要解决批量启停、复用配置还是一对多目标，范围尚未确定。
